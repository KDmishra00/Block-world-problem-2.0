How it works

Blocks World, five predicates, four operators, one stack.

What is Blocks World?

Blocks World is the classic toy planning problem. A robot arm can pick up one block at a time and move it. Blocks rest on the table or on other blocks, and the arm can only take a block that has nothing on top of it. The question is: which moves take us from the start picture to the goal picture?

Its size makes it perfect for studying planning — a few blocks already produce thousands of possible states, but the rules fit on one page.

The five predicates

Everything the planner knows about the world is written with these.

ON(A,B)

Block A sits directly on block B.

ONTABLE(C)

Block C sits directly on the table.

CLEAR(A)

Nothing is on top of A, so the arm can take it.

HOLDING(B)

The arm is holding block B.

ARMEMPTY

The arm holds nothing.

The four operators

Each operator is a precondition list, an add list and a delete list — that is all STRIPS needs.

Operator Preconditions Add list Delete list
PICKUP(x) ONTABLE(x), CLEAR(x), ARMEMPTY HOLDING(x) ONTABLE(x), CLEAR(x), ARMEMPTY
PUTDOWN(x) HOLDING(x) ONTABLE(x), CLEAR(x), ARMEMPTY HOLDING(x)
STACK(x,y) HOLDING(x), CLEAR(y) ON(x,y), CLEAR(x), ARMEMPTY HOLDING(x), CLEAR(y)
UNSTACK(x,y) ON(x,y), CLEAR(x), ARMEMPTY HOLDING(x), CLEAR(y) ON(x,y), CLEAR(x), ARMEMPTY

Goal Stack Planning in five steps

The planner only ever looks at the top of its own stack.

  1. 1

    Push the goals

    The goal conditions go on the stack, first goal on top. The stack now says “what still has to become true”.

  2. 2

    Look at the top

    If the top is a goal that is already true, pop it — nothing to do. This is the “satisfied, forget it” case.

  3. 3

    Choose an operator

    If the goal is false, pick an operator that adds it, push that operator, then push its unmet preconditions above it.

  4. 4

    Execute a ready operator

    When an operator reaches the top, its preconditions have all been handled. Apply its delete list, then its add list, and append it to the plan.

  5. 5

    Repair if it broke

    If a later step destroyed a precondition of an operator still waiting, that operator goes back on the stack with its missing preconditions pushed above it. When the stack is empty, the plan is done.

Goal Stack Planning is not guaranteed to find the shortest plan — it does not search all states. On the Sussman Anomaly it even repeats work, which is exactly why it is worth demonstrating.
